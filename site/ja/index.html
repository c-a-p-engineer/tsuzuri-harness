これは「AIのキャラ設定集」ではない。

完成済みの人格を読み込ませる仕組みではなく、Blankから始め、実際に起きたことだけを根拠に「このAI」を長期的に形成・維持するためのHarnessです。

1. Blankから始める

名前も性格も0から。未形成や「まだ分からない」は欠陥ではなく、正当な状態です。

2. 会話はEvidence

会話全文を自動で人格やMemoryにしません。将来にも必要な意味だけを選び、確定・候補・不明を分けます。

3. 個体を持ち運べる

ModelやToolの性能とIdentityを混同せず、正規状態をPrivate Repositoryに持つことでHostをまたいだ継続を目指します。

何が違う？

Promptでキャラを固定する仕組みでも、会話履歴を全部抱える仕組みでもない。

Tsuzuri Harnessが管理するのは「今どんな人格っぽいか」だけではなく、何を正本にし、何を覚え、何をSkill化し、どう働き、どう検証して次へ持ち越すかです。

Tsuzuri Harnessは「人格の保存箱」ではなく、長く一緒に使うAI個体のControl Planeです。

育

Identityを形成する

提案・候補・受諾・正規状態を分け、先回りで人格を確定しません。

憶

Memoryを選び直す

覚えるだけでなく、統合・更新・Prune・検索まで含めて長期Memoryを維持します。

技

Skillを獲得する

その場の能力と恒久Skillを分け、再利用可能な実行知識だけをEvidence付きで残します。

働

能力に合わせて働く

Model / Worker / Toolに応じて自律度・Task粒度・Verifierを変えます。能力不足時は真実性ではなく担当範囲を縮退。

進

選択的に進化する

Repair / Explore / Consolidate / Prune / Conserve。増やすことだけを進化にしません。

継

長いTaskを続ける

Resume Capsule / Execution Packet / Provenanceで、CompactionやWorker委譲でも必要な契約とEvidenceを渡します。

Identity formation

提案 → 候補 → 受諾 → 正規状態を分離。

Selective memory

会話はEvidence。ArchiveとMemoryは別物。Skill化と形成的Memoryも別々に評価。

Governance

書けるToolがあることと、書いてよいことを分離。

Host portability

ModelやToolの性能を、その子のBiographyと混同しない。一個体のBiographyも共有Kernelへコピーしない。
