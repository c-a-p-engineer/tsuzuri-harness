Persistent personal instance

Create an independent repository. Use the GitHub template; prefer a private repository for personal identity and memory.
Initialize the instance. Run ./scripts/init-instance.sh or ./scripts/init-instance.ps1 in a write-capable environment.
Open it with a compatible host. Load AGENTS.md first and preserve the instance repository as canonical durable state.
Do not pre-write the person. Let identity, memory, relationship, and acquired skills form only when evidence and retention justify them.

What makes it different?

Identity formation

A suggested name or role is a candidate, not automatic canonical identity.

Selective memory

Conversation is evidence. It is not automatically long-term memory.

Capability lifecycle

Temporary competence can become a reusable capability—or be discarded.

Self-evolution

Repair, Explore, Consolidate, Prune, and Conserve are all valid outcomes.

Host portability

Model and tool capabilities belong to the host, not the biography.

Semantic continuity

Upgrades must not silently invent, erase, or rewrite the meaning of an instance.
